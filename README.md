# Household Electricity Consumption Forecasting

A web-based Machine Learning application (BCA final-year major project) that analyses historical household electricity consumption, forecasts future consumption with a **Random Forest Regressor**, evaluates the model and gives energy-saving recommendations.

## 1. Project overview
Users upload a CSV of electricity readings. The app cleans the data, explores patterns, trains a Random Forest, forecasts the next hours/days, shows evaluation metrics, charts, a report and recommendations that quote the evidence from the data.

## 2. Project objectives
- Analyse historical consumption and find high-consumption periods
- Forecast future consumption with a Random Forest Regressor
- Evaluate with MAE, MSE, RMSE and R²
- Provide practical, data-based energy-saving recommendations

## 3. Features
CSV upload and validation · real preprocessing · exploratory analysis · time-based + lag features without data leakage · chronological train/test split · model saving and reuse · multi-step forecasting · evaluation charts · consumption classes (Low/Moderate/High/Peak) · recommendations · prediction history · downloadable report (HTML) and forecast (CSV).

## 6. Machine Learning algorithm
`RandomForestRegressor` (scikit-learn). Many decision trees are trained on bootstrap samples and their predictions are averaged.

- **Target:** consumption at the current time step.
- **Features:** year, month, day, day of week, day of year, week of year, quarter, weekend flag, hour (+ sine/cosine) for hourly data, **lag features** (e.g. 1, 2, 3, 24, 48, 168 hours ago; 1, 2, 7, 14 days for daily data) and **rolling means/std of previous values**.
- **No data leakage:** lags use `shift()`, rolling statistics are computed on the *previous* values only, and the test set is the **most recent** part of the timeline (chronological split, no shuffling).
- After evaluation the model is refitted on all data and saved to `model/trained_model.pkl`.
- Forecasting is **recursive**: each prediction is added to the history and used to build the features for the next step. Long forecasts are therefore less certain.
- Frequency is detected automatically: data finer than ~3 hours is averaged to **hourly**; otherwise **daily**.

## 7. Dataset format
CSV file (separators `,` `;` tab `|` are detected) with:

| Column | Required | Example |
|---|---|---|
| Date/time column (name containing `date`, `time`, `datetime`, `timestamp`) | yes | `2024-05-01 18:00:00` |
| Separate `Time` column | optional | `18:00:00` (used with a `Date` column) |
| Numeric consumption column (e.g. `consumption_kwh`, `Global_active_power`, `usage`) | yes | `1.25` |

```
datetime,consumption_kwh
2024-01-01 00:00:00,0.401
2024-01-01 01:00:00,0.239
```
- Hourly, minute-level or daily data is supported. Minimum: 30 rows to upload; **3 weeks of hourly or 90 days of daily data to train**.
- Missing markers (`?`, `NA`, `null`, empty) are treated as missing values. Day-first and month-first dates are detected automatically.
- The columns are auto-detected and can be changed on the Upload page. Extra columns are ignored.
- `dataset/electricity_consumption.csv` is **SAMPLE DATA** (synthetic, one year of hourly data) for testing only. A few missing values, duplicates and spikes were inserted on purpose to show preprocessing. It was generated by `dataset/generate_sample.py`.

## 9. Installation (Windows)
Install Python 3.9 or newer from python.org (tick **Add Python to PATH**). Open Command Prompt in the project folder.

## 10. Virtual environment setup
```
python -m venv venv
venv\Scripts\activate
```
(PowerShell: if activation is blocked run `Set-ExecutionPolicy -Scope Process RemoteSigned` first. macOS/Linux: `source venv/bin/activate`.)

## 11. Package installation
```
pip install -r requirements.txt
```

## 12. How to run
```
python app.py
```

## 13. Browser URL
Open **http://127.0.0.1:5000** in your browser. Stop the server with `Ctrl + C`.

## 14. Dataset upload instructions
1. Go to **Upload**, choose a `.csv` file (or click *Use bundled SAMPLE DATA*) and press *Upload & inspect*.
2. Check the dataset information (rows, columns, data types, missing values, duplicates, preview).
3. Confirm the date and consumption columns and the unit, then press **Apply preprocessing**.
4. Read the preprocessing report. Uploading new data resets the old model and forecast.

## 15. Model training instructions
Go to **Train**, set the number of trees (default 100), optional max depth and test size, press **Train model**. Then open **Results** for MAE, MSE, RMSE, R² and the actual-vs-predicted chart. Training can take 10-60 seconds for large datasets.

## 16. Forecasting instructions
Go to **Forecast**, pick a period (or an end date), press **Generate forecast**. The table, chart, daily summary and recommendations appear, and the run is stored in **History**. Hourly data: max 30 days; daily data: max 365 days.

## 17. Troubleshooting
| Problem | Solution |
|---|---|
| `python` not recognised | Reinstall Python and tick *Add to PATH*, or use `py -m venv venv` |
| `No module named flask` | Activate the virtual environment, then `pip install -r requirements.txt` |
| Port 5000 already in use | Change `port=5000` at the bottom of `app.py` |
| "Could not detect/ invalid date" error | Select the correct date column on the Upload page; check the date format |
| "Not enough data to train" | Use at least 3 weeks of hourly or 90 days of daily data |
| Saved model not loaded after updating scikit-learn | Click *Train model* again |
| Very large CSV is slow | Use a subset (e.g. one year); minute data is averaged to hourly |
